Open-Source License Compliance

What the Dify license permits Wakeel to do commercially, the two conditions that require action before production rollout, and the recommended path.

1. Executive summary

Wakeel (وكيل) is built on Dify, an open-source LLM application platform by LangGenius, Inc. Dify is licensed under a modified Apache License 2.0 (the "Dify Open Source License"). The license expressly permits commercial use, including using Dify "as a backend service for other applications" — which is exactly Wakeel's architecture. Two additional conditions apply, and both are manageable:

  • Multi-tenancy: one Dify deployment may serve one workspace (tenant) without a commercial license. Wakeel's recommended per-entity deployment model satisfies this by design.
  • Dify console branding: the Dify-provided console frontend must retain the Dify logo and copyright. Wakeel's own portal is unaffected; the embedded workflow editor requires one of three remedies before commercial go-live (Section 5).

Bottom line: Wakeel can be commercialised for Abu Dhabi government entities today under a per-entity deployment model, with one branding remedy applied — or a single commercial/white-label license obtained from LangGenius to clear both conditions at once.

2. The license in brief

Source: LICENSE file, Dify repository (github.com/langgenius/dify), © 2025 LangGenius, Inc.

"Dify may be utilized commercially, including as a backend service for other applications or as an application development platform for enterprises."
Condition (a) — Multi-tenant service: "Unless explicitly authorized by Dify in writing, you may not use the Dify source code to operate a multi-tenant environment. … one tenant corresponds to one workspace."
Condition (b) — Logo and copyright: "In the process of using Dify's frontend, you may not remove or modify the LOGO or copyright information in the Dify console or applications. This restriction is inapplicable to uses of Dify that do not involve its frontend." The frontend is defined as the web/ directory / "web" Docker image.

All other rights and restrictions follow the standard Apache License 2.0. The license also notes Dify's interactive design is protected by an appearance patent, and that LangGenius may revise the license terms.

5. Current Wakeel build — impact assessment

Compliant as-is

  • Wakeel portal UI, server and branding (all original code)
  • Single-workspace deployment (current pilot)
  • All API-level usage: chat-to-build, testing, self-healing, knowledge, providers, marketplace installs

Action before commercial go-live

  • The pilot's rebrand overlay currently replaces the Dify logo/copyright inside the embedded console (Edit tab). Choose one remedy:

R1. Restore Dify branding within the embedded editor only ("Powered by Dify" canvas) — zero cost. R2. Obtain LangGenius' commercial/white-label license — clears conditions (a) and (b) together. R3. Replace the embedded editor with an original, API-driven editing UI (larger build; observe the appearance-patent note).

6. Recommended path

Pilot (now)

Continue the current single-instance evaluation. No license exposure for internal assessment; schedule the branding remedy before any external or paid use.

Adopt per-entity deployments as the standard architecture

One Dify instance per government entity (Azure UAE North or sovereign cloud). This eliminates the multi-tenant condition entirely and aligns with UAE data-residency and security-accreditation requirements.

Apply branding remedy R1, and engage LangGenius in parallel

Restore Dify branding in the embedded editor immediately (compliant at zero cost), while procurement engages LangGenius for an enterprise/white-label license — the preferred end-state for a fully Wakeel-branded product and vendor support.

Maintain Apache 2.0 hygiene

Retain LICENSE and attribution notices in any distributed source; document modifications to the backend; track upstream license changes at each version upgrade.
